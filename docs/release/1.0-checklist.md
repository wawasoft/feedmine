# FeedMine 1.0 Release Checklist

Release branch: `release/1.0`
Base snapshot: `8e684a3a36bbd5ecc3eb037c60f577800e470311`
Target version/build: `1.0 (3)`

This file is the single release checklist for FeedMine 1.0. Until submission, work on `release/1.0`; do not merge old feature branches and do not add new product features.

## Scope lock

### In 1.0
- Welcome → Composer → Feed onboarding
- Start Broad
- Main timeline
- Catalog/source search and Source View
- Text, podcast and video playback
- Bookmarks
- Add feed/URL
- OPML import
- Essential filters
- Curated/personal feed
- Collections, provided smoke tests remain clean
- Smart Feeds/Smart Bookmarks in foreground
- Cached/offline launch behavior already present

### Deferred from 1.0
- Smart Feed background refresh (`BGAppRefreshTask`)
- Explicit download/offline manager
- Share Extension revival
- iCloud sync
- Large architecture/refactoring work
- GitHub Actions / hosted CI

## Local gates — no GitHub Actions

Run from the root of `wsmontes/feedmine-dev` on the release branch.

### Simulator unit tests
```bash
git checkout release/1.0
make clean
make test-sim
```
- [ ] `make test-sim` passes with no unexplained failures

### UI tests
```bash
make test-ui-sim
```
- [ ] Core UI suite passes, or every remaining failure is reviewed and documented as non-blocking

### Static analysis
```bash
make analyze
```
- [ ] No new release-blocking analyzer findings

### Release build
```bash
make build-release
```
- [ ] Release configuration builds successfully on physical device target

## Physical-device smoke test

## Accessibility triage

Do not block 1.0 on zero findings. Fix release-impacting problems only.

- [ ] No clipped/unreachable primary controls
- [ ] VoiceOver labels/actions make sense for primary navigation and feed cards
- [ ] Dynamic Type does not destroy onboarding/core navigation
- [ ] Destructive actions are identifiable and confirm where appropriate
- [ ] Reduce Motion behavior remains usable

## Submission rule

Target submission: September 28–29, 2026.

Once a TestFlight candidate passes the gates, freeze features completely. Only fix defects that can materially stop a user from understanding, using, or trusting FeedMine 1.0.

## Publication to Wawasoft

Do not develop directly in `wawasoft/feedmine` during hardening. When the release candidate is approved locally:

1. Verify the final `release/1.0` SHA and immutable iOS tag.
2. Transfer/merge that exact tested state into the Wawasoft repository using an environment with Wawasoft write credentials.
3. Verify Wawasoft tree SHA/content matches the tested FeedMine Dev release state before App Store submission.
